## Task
Create Meta WhatsApp templates (Arabic, UTILITY, IMAGE header, `{{1}}` = customer name) from the live
platform `https://maxp.online/whatsapp/meta-templates`, plus fix the UX gaps the user reported
("مفيش مكان للكتابة والمتغيرات").

## Bugs found and fixed
1. **Header media upload 500** — `MetaCloudProvider.uploadTemplateMedia` used the one-step
   `/{wabaId}/uploads` call. Replaced with the two-step Resumable Upload API
   (`/{appId}/uploads` → `/{uploadId}` with `Authorization: OAuth`), plus WEBP/BMP/HEIC → JPEG
   conversion and candidate retry. Commit `964580d23`.
2. **`(#100) Unexpected key "headerHandle"`** — `generateComponentExamples` added
   `example.header_handle` but left the internal `headerHandle` key on the component, so *every*
   IMAGE/VIDEO/DOCUMENT header template failed. Now destructures the internal keys out.
   Applies to both `createTemplate` and `updateTemplate`. Test:
   `apps/backend/tests/services/metaCloudProviderCreateTemplateHeaderHandle.test.js`.
3. **Create dialog defaults** — category defaulted to `MARKETING` (review/rejection risk) and
   language reset to `en` on every open. Now defaults to `ar` + `UTILITY` and remembers the last
   choice under `maxp:whatsapp-meta-templates:create-prefs`.
4. **Variables UX** — always-visible variables panel with «إضافة متغير», per-variable sample inputs,
   real `example.body_text` sent to Meta, char counters, visible step pills (the active pill label
   was invisible because of an undefined `--shell-ring` CSS var), scrollable dialog on mobile.
5. **Cancel kept the old form** — closing with إلغاء/X kept body text and variable samples for the
   next open. `closeCreateDialog` now resets form, samples, step and compliance results.
6. **No media guard** — submitting an IMAGE header without an uploaded sample hit Meta with a 500.
   `handleCreate` now blocks it with a clear Arabic message.

### Batch 4 (2026-10-27) — customers replied "أنا مطلبتش أوردر"
Root cause: every earlier template opened with "الموديل اللي حضرتك **طلبت** صورته" / "زي ما **طلبت**",
so recipients read it as "you have an order with us" and pushed back. Fix: drop the words طلب/طلبك from
the premise and add an explicit reassurance sentence.

Gotcha found: `listTemplates` caches the Meta list for 5 minutes (`templateListCache`), so a template
created seconds ago can be missing from the UI even though it exists on Meta (re-creating the same name
then fails with `{"error":"Invalid parameter"}` — that is the duplicate-name error). Wait 5 minutes or
create/delete something to invalidate the cache before assuming a creation failed.

### Batch 6 (2026-10-27) — user's final copy ("مساء الخير أ/ {{1}}")
| name | id | category Meta assigned |
|---|---|---|
| model_photo_new_model_v1 | 1155996370329935 | **MARKETING** (not the UTILITY we requested) |
| model_photo_new_model_utility | 1807181973830604 | UTILITY |

**Key finding:** removing every reference to the customer's own request makes Meta reclassify the template
as MARKETING, even when the create payload says `category: UTILITY` and the create response echoes
UTILITY. Adding one clause ("الموديل الجديد **اللي سألت عنه**") keeps it UTILITY. So a pure "new model"
announcement is marketing by Meta's classifier, no matter how gentle the wording is.

Also: template names must be Latin lowercase + digits + underscore. `sanitizeTemplateName` in
`meta-templates/types.ts` strips every other character, so an Arabic name becomes empty and invalid.
Arabic is only allowed in the header/body/footer content.

Note: a media handle from the resumable upload can be reused for several template creations in a
short window, but goes stale after a while (reusing an old handle returned `{"error":"Invalid parameter"}`).
Upload a fresh image right before a batch.
