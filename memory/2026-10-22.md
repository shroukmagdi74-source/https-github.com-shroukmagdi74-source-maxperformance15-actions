# 2026-10-22 — WhatsApp Meta templates (Swan)

## Task
Create Meta WhatsApp templates (Arabic, UTILITY, IMAGE header, `{{1}}` = customer name) from the live
platform `https://maxp.online/whatsapp/meta-templates`, plus fix the UX gaps the user reported
("مفيش مكان للكتابة والمتغيرات").

## Bugs found and fixed
1. **Header media upload 500** — `MetaCloudProvider.uploadTemplateMedia` used the one-step
   `/{wabaId}/uploads` call. Replaced with the two-step Resumable Upload API
   (`/{appId}/uploads` → `/{uploadId}` with `Authorization: OAuth`), plus WEBP/BMP/HEIC → JPEG
   conversion and candidate retry. Commit `964580d23`.
2. **`(#100) Unexpected key "headerHandle"`** — `generateComponentExamples` added
   `example.header_handle` but left the internal `headerHandle` key on the component, so *every*
   IMAGE/VIDEO/DOCUMENT header template failed. Now destructures the internal keys out.
   Applies to both `createTemplate` and `updateTemplate`. Test:
   `apps/backend/tests/services/metaCloudProviderCreateTemplateHeaderHandle.test.js`.
3. **Create dialog defaults** — category defaulted to `MARKETING` (review/rejection risk) and
   language reset to `en` on every open. Now defaults to `ar` + `UTILITY` and remembers the last
   choice under `maxp:whatsapp-meta-templates:create-prefs`.
4. **Variables UX** — always-visible variables panel with «إضافة متغير», per-variable sample inputs,
   real `example.body_text` sent to Meta, char counters, visible step pills (the active pill label
   was invisible because of an undefined `--shell-ring` CSS var), scrollable dialog on mobile.
5. **Cancel kept the old form** — closing with إلغاء/X kept body text and variable samples for the
   next open. `closeCreateDialog` now resets form, samples, step and compliance results.
6. **No media guard** — submitting an IMAGE header without an uploaded sample hit Meta with a 500.
   `handleCreate` now blocks it with a clear Arabic message.
